# Last Notes

## 2026-05-19 — Як створити глобальний стейдж рекрутингу після встановлення `hr_recruitment_stage_default_fix`

**Контекст.** Модуль `hr_recruitment_stage_default_fix` інвертує стокову поведінку Odoo 17: коли ви тиснете «+ Stage» у kanban вакансії, новий стейдж тепер автоматично прив'язується до цієї вакансії (`job_ids = [current_vacancy]`), а не стає глобальним як раніше. Модуль не блокує можливість створити глобальний стейдж — він лише прибирає випадкове створення «глобалів» з kanban.

### Три способи створити глобальний стейдж

#### 1. Через Configuration → Recruitment → Stages (канонічний шлях)

- Увімкнути Developer Mode: Settings → Developer Tools → *Activate the developer mode*
  - Меню Stages у стоці має `groups="base.group_no_one"` (`odoo17_enterprise/odoo/addons/hr_recruitment/views/hr_applicant_views.xml:569`) — без Dev Mode його не видно.
- Recruitment → **Configuration → Stages → New**
- Залишити поле **Job Specific** порожнім → Save.
- У цього action немає `default_job_id` у контексті, тож умова інверсії у fix не спрацьовує → `job_ids` лишається порожнім → стейдж глобальний.

#### 2. Створити з kanban і вручну очистити `Job Specific`

- У kanban вакансії → «+ Stage» → ввести назву → стейдж створюється job-specific (`job_ids = [поточна вакансія]`).
- Відкрити форму нового стейджа (шестерня в заголовку колонки → **Edit Stage**, або через Configuration → Stages).
- Видалити всі теги-вакансії з поля **Job Specific** → Save.
- Тепер стейдж глобальний.
- Працює без Developer Mode, але менш елегантно (треба зробити зайвий крок очистки).

#### 3. Escape hatch `hr_recruitment_stage_mono` (для коду/інтеграцій)

- При програмному створенні стейджа передати у context `hr_recruitment_stage_mono=True`.
- Fix модуль поважає цей прапор (`jito_modules/hr_recruitment_stage_default_fix/models/hr_recruitment_stage.py:20`) і не виконує інверсію → повертається стокова поведінка (job_id викидається з контексту → стейдж глобальний).
- Призначення: міграційні скрипти, server actions, кастомні інтеграції. Звичайним користувачам це не потрібно.

### Рекомендація

- Глобальні стейджі зазвичай створюються рідко (вони описують увесь процес рекрутингу, а не одну вакансію) → **спосіб 1** правильніший: робить намір явним.
- Якщо знадобиться створювати глобальні стейджі регулярно без Developer Mode — можна розширити fix модуль (зняти `group_no_one` з меню Stages або додати окрему кнопку «New Global Stage» у Settings рекрутингу).

### Як зрозуміти, що стейдж глобальний

- Відкрити стейдж → поле **Job Specific** порожнє → глобальний (видимий у всіх вакансіях).
- Якщо у `Job Specific` є хоч одна вакансія → стейдж видимий **тільки** у перелічених вакансіях.
